## 2. What went well

### 2.1 The adversarial three-layer code review was the highest-yield process we ran

Every one of 21 stories went through Blind Hunter / Edge Case Hunter / Acceptance Auditor, and the
yield was never trivial — **14 to 29 patches per story**, applied *after* the story's own tests were
green and its build chain passed. Representative finds:

- **Story 2.6 — tap-to-position mapped `clientX` through the wrong plot origin.** recharts adds the
  y-axis's own width to `offset.left`, so the true origin was 68, not 34; a left-edge tap landed
  ~17 samples late, decaying to exactly zero at the right edge. **Found independently by two
  layers.** The unit test had been handed the caller's own wrong numbers, so it *confirmed* the bug.
- **Story 2.6 — the `next/dynamic` code-split was defeated by a single value import.**
  `CHART_HEIGHT_CLASS` created a static module-graph edge into the deferred module; a **316 kB
  recharts chunk shipped to routes with no chart**, including m002. The completion notes had
  attributed it to "Next's static export" — a wrong explanation sitting on top of a real defect.
- **Story 2.7 — the light theme was unreadable on pitch.** Five on-pitch tokens at **1.45–2.05:1**,
  taken to 4.58–11.14:1.
- **Story 2.12 — a raw NUL byte in `TableSortMenu.tsx`** made git treat the whole file as binary.

### 2.2 Validate the harness before trusting the number

Established in 2.6 ("the method was validated before any new number was trusted"), cited by name in
2.13, and vindicated twice in 2.19:

- **`python -m http.server` was not a model of the host.** Single-threaded, no compression. Serving
  the export the way Netlify serves it moved the Match Dashboard **53 → 79** with zero code change.
- **A single Lighthouse run was not a measurement.** Between two builds, untouched routes moved
  99→91 and 88→66. The first pass of that work drew a conclusion from single runs and said so.
- Story 2.19 Task 9 found a **caching defect only the live host revealed** — `_next/static/*` was
  paying a conditional round-trip per asset because the local harness had assumed `immutable`.

### 2.3 Decisions were escalated with evidence, never guessed

2.9 overturned an epic premise and re-scoped in-story. 2.10 took four rulings at creation. 2.11 split
three ways. 2.19 put Q1–Q5 up with measured figures attached. No story quietly picked an option.

### 2.4 Parallel sessions worked

**Juan's assessment, recorded:** parallel sessions were worth it on net. They worked *because*
sessions self-policed — 2.18 aborting at its own rule, 2.11a verifying in an isolated worktree.

## 3. Where we struggled

### 3.1 Concurrent sessions on a shared tree — cost paid, protocol implicit

- **Story 2.18 stopped itself** after Task 7: the 2.11a session held `es.ts`, `en.ts` and
  `i18n.test.ts`, the exact files Task 8 had to *modify* rather than append to.
- **Story 2.11a had to verify its full chain in an isolated worktree** because 2.18 had left the
  shared tree non-compiling.
- **Commit attribution leaked.** 2.11a's code reached `main` inside `54f7093` and `0c407b3`,
  captured by other sessions' sweeping `git add`, never under its own commit. D13 exists because
  this had already happened twice — 2.14→2.15 and 1.14→2.6.

**Resolution:** parallelism stays. The residual defect is attribution, not concurrency, and the
protocol that made it work was rediscovered per story instead of written down once.

### 3.2 Story specs needed a validation pass to be implementable

- **2.6:** the `--shot-goal-light` token mechanism was **unimplementable** — no such property exists
  in the codebase. The `<md` presentation and the chart height were **entirely absent**. Chart-overlay
  positioning had no mechanism. Decision count 22 → 27.
- **2.10:** validation closed **seventeen** implementability gaps, **four of them build-breaking**.
- **2.11a:** table inventory corrected 9 → 10; the sticky-header clause found unimplementable inside
  `ViewDataDisclosure`.

**Resolution:** **Juan's ruling — create-light / validate-hard is the right trade and stays.**
Validation is therefore a *stage*, not a rescue, and is written up as a required step below.

### 3.3 Tests that passed for the wrong reason — a recurring class, four instances

- **`match-hero.test.ts` stayed green by coincidence** at the DATA_ROOT cutover: m001 and m074 exist
  in both corpora with the same ids. The record calls this "the worse outcome of the two" — its
  sibling `tactical-sections.test.ts` went red honestly and got fixed.
- **The Hub's export test checked 3 boards of 36** — 8% coverage, silently — because it drove its
  loop off the *fixture* leaderboards while asserting against the *exported* page.
- **2.6's unit test was fed the caller's own wrong numbers**, confirming the tap-to-position defect.
- **"The third gate-that-cannot-fail this project has shipped"** (1.16): the payload budget gate sat
  at 3.4% of its cap and could not go red. 2.19 also found the schema-version test's *name* had been
  wrong before the flip.

This is the highest-priority systemic finding in the retrospective.

### 3.4 AC 2 shipped unmet

Lighthouse mobile 83 / 68 against a floor of 90. The two routes fail for **different** reasons: the
Hub had density SM-C2 could move; the Match Dashboard had 638 DOM nodes and **zero** tables, so its
cost is script evaluation, not density. **Juan's ruling: SM-5 stays closed. It is not Epic 3 scope.**

---

## 4. Key takeaways

1. **Adversarial review earns its cost every time.** ~330 patches on already-green code. Two of the
   most expensive defects were found only because a *second independent layer* looked.
2. **A measurement is not a number — it is a number plus a validated harness.** Both times we
   skipped that, the conclusion was worthless and had to be redone.
3. **A green test is not evidence until it has been proven capable of going red.** Four instances.
4. **Parallelism is fine; implicit coordination is not.** The protocol worked and was never written
   down.
5. **Run the retrospective.** Epic 1's was skipped, and its concurrent-session lesson had to be
   re-learned inside Epic 2.

### 6.2 ⚠️ BLOCKER — Epic 3 cannot be written until one ruling is taken

The SEO ask ("English or Spanish depending on the user zone") collides with three shipped decisions:

- **D17** — ES canonical for `<title>`/OG, ruled 2026-08-25
- **AR-11's `og:image` reading** — the code bans `og:image` as an "external/asset request"; AR-11
  (`epics.md:92`) actually concerns *fonts and third-party origins*. A **same-origin** OG card does
  not violate it. The ban is a self-imposed over-reading, pinned by three tests.
- **AD-13 / NFR-8 / NFR-9** — no functions, no middleware, $0

Share previews are rendered by crawlers, which have no user, no geolocation and no JavaScript. One
URL yields one document. Options: **(1)** accept ES canonical (0 work); **(2)** per-locale URLs with
`hreflang` — the standard answer, ~1,406 → ~2,812 routes, reopens D17; **(3)** a Netlify Edge
Function — breaks AD-13 and the $0 property.

**Recommended:** run `bmad-correct-course` to take this ruling **before** `bmad-create-epics-and-stories`.

### 6.3 Available without any ruling

Newly unblocked by the domain purchase alone: `metadataBase`, absolute canonical URLs,
`sitemap.xml`, `robots.txt`, a Twitter card, a same-origin `og:image`, and first-visit locale
detection from `navigator.language` (`bootstrap.ts` currently has none and defaults every new
visitor to Spanish).

### 6.4 Constraint on the home refactor

The home page **is** the Tournament Hub whose density Story 2.19 moved behind SM-C2 disclosures to
recover Lighthouse points. With SM-5 ruled closed, the refactor is **not** designing toward 90 —
but it carries a **guard, not a goal**: *free to reshape, not free to regress below the recorded
Hub baseline of 68.* Re-measure per D4 (median of 3, mobile, host-realistic server).
